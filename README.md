# Issue Tracker API

A simple issue-tracking REST API built with FastAPI. Issues are persisted to a local JSON file, so there's no database to set up.

## Features

- Full CRUD for issues (create, read, update, delete)
- Input validation with Pydantic, including status and priority enums
- JSON-file storage, no external database required
- CORS enabled for all origins
- `X-Process-Time` response header on every request (timing middleware)

## Tech stack

- Python 3.12+
- FastAPI
- Pydantic
- [uv](https://docs.astral.sh/uv/) for dependency management

## Getting started

### Prerequisites

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/getting-started/installation/) installed

### Installation

```bash
git clone https://github.com/Tijani891/fastapi-issue-tracker.git
cd fastapi-issue-tracker
uv sync
```

### Running the server

```bash
uv run fastapi dev main.py
```

The API will be available at `http://127.0.0.1:8000`.

Interactive docs:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

## API reference

Base path: `/api/v1/issues`

| Method | Endpoint | Description | Success status |
| ------ | -------- | ----------- | -------------- |
| GET | `/api/v1/issues/` | List all issues | 200 |
| POST | `/api/v1/issues/` | Create a new issue | 201 |
| GET | `/api/v1/issues/{issue_id}` | Get a single issue by ID | 200 |
| PUT | `/api/v1/issues/{issue_id}` | Update an issue | 200 |
| DELETE | `/api/v1/issues/{issue_id}` | Delete an issue | 204 |

### Issue fields

| Field | Type | Notes |
| ----- | ---- | ----- |
| `id` | string | UUID, generated by the server |
| `title` | string | 3–100 characters |
| `description` | string | 5–1000 characters |
| `status` | enum | `open`, `in_progress`, `closed` (default `open`) |
| `priority` | enum | `low`, `medium`, `high` (default `medium`) |

On create, only `title`, `description`, `status`, and `priority` are accepted; the `id` is assigned automatically. On update, every field is optional, so you can send just the ones you want to change.

### Example: create an issue

```bash
curl -X POST http://127.0.0.1:8000/api/v1/issues/ \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Login button unresponsive",
    "description": "The login button does nothing on the first click.",
    "status": "open",
    "priority": "high"
  }'
```

Response:

```json
{
  "id": "3f2a9c7e-1b4d-4e8a-9f6c-2d1e0a5b7c3f",
  "title": "Login button unresponsive",
  "description": "The login button does nothing on the first click.",
  "status": "open",
  "priority": "high"
}
```

### Example: update an issue

```bash
curl -X PUT http://127.0.0.1:8000/api/v1/issues/3f2a9c7e-1b4d-4e8a-9f6c-2d1e0a5b7c3f \
  -H "Content-Type: application/json" \
  -d '{ "status": "closed" }'
```

## Storage

Issues are stored in `data/issues.json`. The file and its folder are created automatically on the first write, so you don't need to set anything up in advance.
